Quickstart

Build once. Launch every rank.

Compile the runtime, link a C program, and create a local rank mesh in a few commands.

Prerequisites

macMPI targets macOS on Apple Silicon and depends on Darwin-specific process, event, and shared-memory APIs.

Apple ClangXcode Command Line Tools
CMake ≥ 3.20Project configuration
NinjaIncremental builds

Build

Configure an out-of-tree build from the repository root. The default target produces the shared library, launcher, tests, and benchmarks.

Terminal
# Clone and enter the repository
git clone https://github.com/Hardikgupta1709/macMpi.git
cd macMpi

# Configure and compile
cmake -S . -B build -G Ninja
cmake --build build

First program

Every rank enters through the same executable. The launcher assigns identity and topology before MPI_Init attaches the process to the runtime.

hello_mpi.c
#include "mpi.h"
#include <stdio.h>

int main(int argc, char **argv) {
  MPI_Init(&argc, &argv);

  int rank, size;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  printf("Hello from rank %d of %d\n", rank, size);
  MPI_Finalize();
  return 0;
}
Launch eight local ranks
./build/mpirun -n 8 ./build/hello_mpi
!
Launch through mpirun

Starting an MPI binary directly leaves its rank, universe, and peer-socket environment undefined.

Architecture

Control stays small. Payloads stay in memory.

macMPI separates orchestration, progress, signaling, and payload movement so the application thread stays out of the hot path.

System model

Every rank is a separate process. All ranks map one shared-memory object and inherit a full mesh of Unix-domain sockets from the launcher.

R164 MB slab
R264 MB slab
R364 MB slab
Unified shared memory/macmpi_data_plane

Hybrid transport

The sender copies bytes into its shared slab, then sends a compact routing header that tells the receiver where the payload lives.

PlaneMechanismPurpose
ControlUnix socket64-byte header and receiver notification
DataPOSIX SHMPayload stored at a per-rank slab offset
i
Why the split matters

Large buffers avoid the kernel socket-copy path while socket readiness still gives the engine efficient event-driven wakeups.

Progress engine

A dedicated pthread owns transport progress. The application posts a request, continues computing, or waits on a condition variable.

01Post

MPI_Isend or MPI_Irecv creates an internal request.

02Dispatch

The engine drains its queue and monitors peer descriptors with kqueue.

03Match

Incoming headers match active receives by source and tag.

04Complete

The engine copies payload bytes and signals the waiting application thread.

Messages that arrive before a receive is posted enter the Unexpected Message Queue and are extracted when a matching request appears.

Process runtime

mpirun constructs the peer socket mesh before forking. Each child closes unrelated descriptors, receives topology through the environment, redirects output to a private pipe, and replaces itself with the target program.

MPI_RANKCurrent process rank.
MPI_UNIVERSE_SIZETotal number of local ranks.
MPI_SOCKET_FDSComma-separated inherited peer descriptors.
API reference

Typed messages. Explicit completion.

Send buffers between ranks with blocking convenience calls or non-blocking request handles.

Lifecycle

MPI_Init(argc, argv)Map shared memory, parse topology, and start transport progress.
MPI_Comm_rank(comm, &rank)Read the caller's rank in a communicator.
MPI_Comm_size(comm, &size)Read the communicator's process count.
MPI_Finalize()Synchronize, stop progress, unmap memory, and close peers.

Point-to-point

Blocking calls post one internal request and immediately wait for completion. Non-blocking calls return after queueing work.

MPI_Send(buf, count, type, dest, tag, comm)Send a typed buffer and wait until transport completes.
MPI_Recv(buf, count, type, source, tag, comm, status)Receive a matching buffer and wait for completion.
MPI_Isend(..., &request)Post a send and return a request handle.
MPI_Irecv(..., &request)Post a receive and return a request handle.
MPI_Wait(&request, status)Sleep until the request completes, then release it.
MPI_Test(&request, &flag, status)Check completion without blocking.
Non-blocking receive
MPI_Request request;
MPI_Irecv(buffer, count, MPI_DOUBLE, source, tag,

// Independent work can overlap communication.
MPI_Wait(&request, MPI_STATUS_IGNORE);

Datatypes & ops

Built-in contiguous datatypes cover the current transport. Derived datatype construction is planned.

MPI_INTMPI_FLOATMPI_DOUBLEMPI_CHARMPI_BYTE

Reductions support MPI_SUM, MPI_MAX, MPI_MIN, and MPI_PROD.

Collectives

Coordinate ranks without a serial center.

Tree and dissemination structures spread synchronization and data movement across the communicator.

Synchronization

MPI_Barrier uses dissemination rounds. At round k, each rank exchanges a token with peers offset by 2k, giving logarithmic round depth.

MPI_Bcast maps the selected root to virtual rank zero and expands a binomial tree one power of two per round.

Data movement

ROOT → ALLMPI_Bcast

Replicate one typed buffer through a binomial tree.

ROOT → SLICESMPI_Scatter

Partition a root-owned buffer across ordered ranks.

SLICES → ROOTMPI_Gather

Collect rank-local slices into root-owned storage.

ALL → ALLMPI_Allgather

Gather at rank zero, then broadcast the complete array.

ALL ⇄ ALLMPI_Alltoall

Exchange one peer-specific slice with every other rank.

TREE → ALLMPI_Allreduce

Reduce through an inverse tree, then broadcast the result.

Reduction

MPI_Reduce combines rank-local values up an inverse binary tree. MPI_Allreduce composes that operation with broadcast so every rank receives the result.

Global sum
double local = compute_partial_result();
double total = 0.0;

MPI_Allreduce(&local, &total, 1, MPI_DOUBLE,
              MPI_SUM, MPI_COMM_WORLD);
